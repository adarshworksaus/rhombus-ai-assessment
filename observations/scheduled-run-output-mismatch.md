# Scheduled Run Output / Execution History Mismatch

## Scenario

Tested whether a Rhombus AI pipeline configured with an Amazon S3 source and Google Cloud Storage destination executes correctly when triggered by a schedule.

The pipeline had previously completed successfully through a manual execution and produced an output object in the configured GCS bucket.

## Expected Behaviour

When the scheduled execution runs successfully:

1. The complete pipeline should execute.
2. The configured Data Output node should write the cleaned CSV to GCS.
3. The scheduled run should appear in the Rhombus Executions view.
4. Logs and execution history should consistently represent the run status.

## Observed Behaviour

The scheduled pipeline was tested multiple times.

Rhombus Logs reported:

- "Pipeline execution started."
- "Pipeline execution completed successfully."

A controlled scheduled run configured for 1:25 AM executed at approximately 1:26 AM and was reported as successful.

However:

- No new output object appeared in the configured GCS bucket.
- The only GCS object remained the output generated by the earlier manual run, created at 00:41:53.
- The Rhombus Executions page continued to display "No results."
- No failure was reported in the visible Rhombus logs.

The behaviour was reproduced across scheduled executions.

## Result

**Unexpected behaviour / potential platform issue**

The scheduler successfully triggers an execution according to Rhombus Logs, but the successful status does not correspond to a new object being written by the configured GCS Data Output node.

Additionally, the scheduled execution is not represented in the Executions view.

## Impact

This creates a reliability and observability issue for scheduled ETL workflows.

A user relying only on the visible success log could reasonably assume that the ETL process completed and delivered its output, even though the expected destination object was not created.

The missing execution-history entry also makes scheduled-run auditing and troubleshooting more difficult.

## Evidence

Evidence captured during testing includes:

- Rhombus schedule shown as Active.
- Rhombus Logs showing scheduled pipeline execution started and completed successfully.
- Rhombus Executions view showing "No results."
- GCS bucket showing only the earlier manually generated output object.

## Notes

The manual pipeline execution successfully produced an object in the same configured GCS destination before the scheduled tests. This indicates that the destination connection itself was capable of receiving pipeline output during manual execution.

Further investigation would be required to determine whether the issue is caused by scheduled execution handling, Data Output node behaviour during scheduled runs, or execution-status reporting.
